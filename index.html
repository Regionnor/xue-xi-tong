学习通AI答题小助手（Region改良款）

运行在超星学习通网页上的用户脚本。最大特色是接入任意 OpenAI 兼容的 AI 接口来完成答题， 不依赖任何第三方题库；同时保留视频自动播放、文档自动阅读、章节测试 / 作业 / 考试自动完成等能力。

项目简介

从 ScriptCat #711 改良而来，专注超星学习通 + 自有 AI 接口。

本项目基于 ScriptCat #711《超星学习通｜知到智慧树——网课小助手》（原版 v0.2.7）改良， 在此向原作者致敬。改良款做了三件核心的事：砍掉第三方题库、只保留超星学习通、把答题能力交给你自己的 AI。

脚本在页面加载时只创建一个极轻量的悬浮按钮，点击后才挂载面板，因此不会拖慢超星页面； 面板内部已完全不依赖 ElementPlus，全部使用原生组件实现，打开与点击都不再卡顿。

v1.28–v1.35 集中修复了视频播放链路与章节自动推进：先确认视频真的在播放，再设倍速、再拖进度； 遇到课程禁用倍速或拖拽时自动保持 1x；播完后按选择器、可见文本、iframe、章节卡片标签多级兜底进入下一个任务点。

OpenAI 兼容接口 无题库依赖 原生面板 · 不卡顿 GitHub Pages 自动更新

核心特性

功能按「答题 / 学习流程 / 面板 / 更新」四类整理。

AI 自动答题

对接任意 OpenAI 兼容接口（OpenAI、DeepSeek、通义千问、豆包、Kimi、小米 MiMo、本地 Ollama 等），把题干与选项发给你的 AI，解析回复后自动填入。

全题型支持

单选、多选、判断、填空、简答均可处理，不依赖任何题库与题库密钥。

预设接口源 + 一键测试

「答题」页内置预设下拉，选中即填好接口地址；点「测试连接」用极简 ping 请求验证地址 / 密钥 / 模型是否可用，并显示失败原因。

视频自动播放与顺序保障

等播放器就绪（readyState ≥ 2）再播放，并校验进度确实在推进；确认播起来之后才设倍速、才尝试拖拽。设速后若播放被中断会自动回退 1x，避免「画面动一下就停」。

文档 / PPT 自动阅读

递归进入嵌套 iframe，滑动到真正的内容渲染层，自动完成文档、PDF 的阅读任务点。

视频智能加速与限制识别

自动选取播放器允许的最高倍速（默认 2x），并可拖到结尾前几秒快速完成。任务点若标注「不可倍速 / 不可拖拽 / 观看时长 ≥ 90%」，自动保持 1x 且不拖进度；同一视频只跳一次，已播完的不再重播。

自动推进到下一任务

视频播完 / 文档滑完后，按「固定选择器 → 页面可见文本 → iframe 内文本 → 章节卡片标签」逐级兜底进入下一节；点完会校验页面是否真的变了，没变就换下一种方式重试。

覆盖主要场景

视频任务点、章节测试、作业、考试均可自动完成；支持自动提交与正确率阈值策略。

运行日志与诊断导出

「首页」实时显示运行日志（播放状态、倍速 / 拖拽结果、进入下一节的命中方式、卡片切换诊断等），可一键导出为 .txt，排查问题直接发日志即可。

轻量原生面板

面板已移除 ElementPlus，全部原生实现；页面加载只创建一个悬浮按钮，点击才挂载，打开不卡、点击不卡。

自动检查更新

更新地址使用 GitHub Pages（约 10 分钟缓存），发布新版本后很快就能收到更新提示。

常见问题

按「现象 → 原因 → 处理」整理。

点了「AI」按钮，面板打不开 / 没反应

先确认版本：1.22 存在一个渲染崩溃问题，会导致面板无法挂载，1.23 已修复。请在管理器里查看脚本版本，低于 1.23 请更新。

1.23 起，如果挂载仍然失败，页面左下角会出现一条红色错误提示条（约 8 秒），把上面的文字反馈即可定位。

另外请确认脚本为启用状态，且当前页面域名在「生效域名」范围内。

页面上出现了两个「AI」按钮，只有一个能用

这是 1.23 及更早版本的问题：脚本会注入到所有 *.chaoxing.com 的 iframe，每个 iframe 都创建了一个悬浮按钮，但只有顶层那个能打开全屏面板。

1.24 起已限制为只在顶层页面创建按钮与面板，更新后多余按钮会消失。

切换标签后，内容变了但顶部高亮没变

1.26 之前的问题：标签按钮的编译优化标记缺少 class 更新位，导致高亮不重算。

1.26 起已修复，点击哪个标签，高亮就跟着走。

我已经进了答题页，面板却还显示「首页」

1.25 起，面板会根据页面地址自动选择标签：studentstudy、dowork、/work、homework、exam、mooc-ans 等页面显示「答题」，其余显示「首页」。

如果你的答题页地址比较特殊、没有被规则覆盖，可以手动点「答题」，或把地址反馈给作者加入规则。

更新了新版本，但脚本还是旧版

先确认版本：面板「首页」的第一条日志会打印「脚本加载成功，正在解析网页（当前版本 vX.Y）」，也可在管理器里查看。

更新地址已从 jsDelivr 换成 GitHub Pages（缓存约 10 分钟）。若刚发布不久，等几分钟或在管理器里手动点「检查更新」；仍是旧版可重新打开安装地址覆盖安装。

注意：从旧版本（jsDelivr 更新通道）升级时，需要手动重装一次新地址，之后才会走 Pages 通道。

日志提示「该页面无任务，请进入章节或答题页面使用」

说明当前页面（如课程详情页）没有可执行的任务点。进入具体章节、作业或考试页面即可。

DeepSeek 该填哪个模型？为什么旧模型名用不了？

DeepSeek 官方文档目前只提供两个模型：deepseek-flash（DeepSeek-V4.1-Flash）与 deepseek-v4-pro（DeepSeek-V4-Pro）。旧版 chat 系列模型名已下线，填了会返回「模型不存在 / Model Not Exists」。

官方 OpenAI 格式地址是 https://api.deepseek.com（不带 /v1），脚本会自动拼接 /chat/completions。v1.36 起选中 DeepSeek 预设即填入该地址，模型框也会直接提示这两个模型名。

模型框留空时，v1.36 起会自动兜底为 deepseek-flash；旧版本会错误地把 gpt-4o-mini 发给 DeepSeek，导致「测试连接」与答题都失败。

「测试连接」失败：请求出错 / 超时 / 返回异常
  • 多数服务需填 OpenAI 兼容的 /v1 基址（如 https://api.openai.com/v1）；DeepSeek 官方写法是 https://api.deepseek.com（不带 /v1）。都不要带 /chat/completions，脚本会自动拼接。
  • 确认 API Key 正确、未过期，且账户有额度。
  • 确认模型名与所填接口匹配（不同服务商模型名不同）。
  • 超时时间为 20 秒；网络不稳定或被墙时可能失败，可换网络重试。
  • 返回异常时，提示里会带 HTTP 状态码与响应片段，可据此判断是鉴权、模型不存在还是余额问题。
学习通界面上没有倍速选项，脚本还会开倍速吗？

会先尝试，但会验证，不会硬来。脚本优先读取播放器速度菜单的最高档；读不到就尝试 2x，不生效再降到 1.75 / 1.5 / 1.25，最后保持 1x。

1.28 起还会扫描任务点文案，一旦出现「不可倍速 / 不可拖拽 / 无法拖动进度条 / 观看时长 ≥ 90%」等限制，直接保持 1x 正常播放，且不拖进度条。

1.30 起顺序改为「先播放并确认进度真的在推进 → 再设倍速 → 再拖拽」；设速后 1.8 秒内若播放被中断，会自动回退 1x 继续播。所以没有倍速选项时可能短暂尝试，但不会一直强设倍速、更不会把视频卡住。

视频无法自动播放 / 手动点播放后画面动一下就停

多见于标注「观看时长 ≥ 90%、不可倍速、不可拖拽」的任务点：1.27 及更早版本一上来就强设 2x，播放器会把速度打回甚至暂停；同时 play() 在播放器尚未初始化（duration 都取不到）时被调用，会抛 AbortError。

1.28 起：等就绪 + 校验 + 重试——先等 readyState ≥ 2（最多 3 秒）再播；每次播放后校验 1.2 秒内 currentTime 是否真的推进，未推进就点播放器按钮重试（最多 4 次），不再「点一次就算成功」。恢复播放被拒绝可重试 8 次；速度被播放器改回时最多纠正 3 次即放弃，避免来回拉锯。

1.30 起：applyMediaOptimizations() 从 play() 之前移到播放确认之后；video.paused 为真时直接跳过拖拽，日志写明「视频尚未开始播放，暂不拖拽进度条」。1.31 起还移除了播放前的强制 pause()，避免与播放器状态机冲突。

日志停在「准备播放」，一直不出现「播放成功」

这是 1.28–1.30 的一个单位错误：项目里 sleep(second) 的参数单位是「秒」（内部 × 1000），而新增的重试逻辑误传了毫秒——sleep(1200) 实际等 20 分钟、sleep(2500) 等约 42 分钟，播放确认循环直接卡死，后续倍速 / 拖拽 / 下一节全部不会执行。

1.31 已改为 sleep(1.2) / sleep(2.5)，并在定义处标注单位；同时补全「播放流程已结束」「页面已切换」「任务点已完成」「检测到视频弹题」等分支日志与播放状态诊断。低于 1.31 请更新。

视频播完 / 文档滑完，不自动进入下一个任务或章节

1.28 及更早版本进入下一节只靠 5 个固定选择器、且只在顶层文档查找；新版学习通按钮结构变化后全部落空。1.29 起改为三级兜底：① 原选择器 → ② 顶层按可见文本（下一节 / 下一小节 / 下一任务 / 继续学习等）→ ③ 逐个进入同源 iframe 做同样匹配，并加可见性判断与 2.5 秒后重试。

若章节里其实是 1 Case 1 / 2 Case 2 / 3 Case 3 这类卡片标签（日志表现为点了「下一节」后 iframe 列表完全没变），1.34 起会在点击后比对页面签名（location.href + 顶层 iframe.src），没变化就改点下一个卡片标签；找不到时 2.5 秒后再走一轮兜底。

1.35 起，卡片切换失败还会输出「当前激活元素文案」诊断。如果仍然停住，请把导出的日志发来（尤其是这一行），就能按真实标签结构补上匹配规则。

视频播完又重播一遍，再自动跳到末尾

跳转到末尾可能被「观看时长 ≥ 90%」判定未完成，播放器把视频复位重播；下一轮处理又跳一次，形成「播完 → 重播 → 跳末尾」的循环。

1.32 曾默认关闭自动 seek，但按用户要求 1.33 已恢复默认开启，保留原有的极速刷完体验；同时用 seekedVideoSrcs 保证同一视频在本次章节内最多只跳一次。1.34 又新增 completedVideoSrcs：本页已自然播完的视频被复位后直接跳过，日志「该视频本页已播放完成，跳过重播」。

若某门课仍因此重播，可把脚本内 ENABLE_AUTO_SEEK 改为 false，退回纯倍速播完。

视频不加速 / 不会自动跳到末尾

倍速上限由播放器开放程度决定：优先读速度菜单最高档，读不到尝试 2x，仍不生效则降级到 1.75 / 1.5 / 1.25，最后保持 1x；命中课程限制文案时直接保持 1x（详见本页「学习通界面上没有倍速选项，脚本还会开倍速吗？」）。

自动跳到结尾前 5 秒在 v1.33 起默认开启（ENABLE_AUTO_SEEK = true），且只在「已确认视频真的在播放」之后才执行。若某门课要求「观看时长 ≥ 90%」，跳转可能被判未完成并导致复位重播；这种情况可把 ENABLE_AUTO_SEEK 改为 false，改为纯倍速播完。同一视频在本次章节内只会跳一次。

配置会丢吗？换浏览器还在吗？

配置会保存在脚本存储（以及同源的 localStorage）中，刷新、重开页面都会保留。换浏览器 / 换设备不会自动同步，需要重新填写。
